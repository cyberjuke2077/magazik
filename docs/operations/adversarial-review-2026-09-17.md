# Адверсариальное ревью Electromagaz - 17 сентября 2026

## Решение о запуске

Открытый коммерческий запуск пока не рекомендован. Работает базовая B2B-витрина с корзиной и запросом КП, но найдены проблемы безопасности зависимостей, противоречие в обработке персональных данных, потеря коммерческих правок при публикации каталога и ошибки покупательского сценария.

Проверенный исходный commit: `2bd5d94480eb24e359a0bba10c232699ab5b88b5`. Локальный `main` совпал с актуальным GitHub `refs/heads/main` через `git ls-remote`. Проверена публичная витрина https://electromagaz-production.vercel.app. Точный SHA текущего Vercel deployment в этом ревью не проверялся: совпадение интерфейса с кодом не заменяет такую проверку.

Целевая база подтверждена через API: `37Lunar's Org / 37Lunar's Project`, ref `dbumwpnbtvixfusxnggn`, PostgreSQL 17.6, регион `eu-west-3`. Снимок агрегатов каталога находится в [live-metrics.md](../../live-metrics.md). Персональные данные клиентов не извлекались.

Приоритеты: P1 - закрыть до публичного запуска; P2 - исправить в ближайшем цикле, до активации соответствующего сценария. Подтверждение версии с известной уязвимостью не означает доказанный взлом production.

## Находки

### R1. P1 - уязвимые Next.js и sharp

**Код:** `package.json:55-60`, `package-lock.json`, `next.config.ts:22-31`, `src/lib/storage/r2-client.ts:172`.

Зафиксированы Next.js `16.3.0` и sharp `0.35.3`. Актуальный `npm audit --omit=dev` выявил три уязвимых пакета: Next.js critical, sharp high, csv-parse moderate. Для Next.js и sharp подтверждены advisory разработчиков о возможном выполнении кода при обработке специально подготовленного AVIF. В проекте используется оптимизация изображений Next.js и непосредственная обработка внешних изображений через sharp.

Условие эксплуатации - попадание вредоносного изображения в доступный обработчику источник; сама возможность загрузки произвольного файла посетителем не найдена. Наличие защиты на управляемой инфраструктуре Vercel отдельно не проверялось. Windows-specific advisory Next.js не переносится автоматически на Vercel.

**Исправление:** обновить Next.js как минимум до исправленной линии `16.3.3+`, sharp до `0.35.4+`, согласовать eslint-config-next, обновить lockfile и повторить audit, build и image smoke. Версии исправлений подтверждены [Next.js advisory](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4) и [sharp advisory](https://github.com/lovell/sharp/security/advisories/GHSA-rgj7-g3m4-5g8c).

### R2. P1 - политика хранения ПДн противоречит фактической базе

**Код:** `src/app/privacy/page.tsx:41-54`, `src/app/request-list/actions.ts:71-88`, `src/lib/notifications.ts:69-79`.

Публичная страница `/privacy` обещает хранение персональных данных на территории РФ. Подтверждённый регион целевой Supabase - `eu-west-3`. Заявки содержат контактное лицо, телефон, email и адрес и сохраняются в этой базе. Кроме того, код отправляет контакты в Telegram при наличии конфигурации; это не отражено в перечне получателей политики. Фактическая настройка Telegram в production не проверялась.

**Исправление:** согласовать реальную архитектуру хранения и передачи ПДн и привести опубликованные условия в соответствие с ней до приёма реальных заявок. Простая правка обещания в тексте не доказывает соответствие требованиям российского запуска. Это подтверждённое техническое противоречие, а не заключение о юридической квалификации нарушения.

### R3. P1 - публикация каталога стирает коммерческие изменения админки

**Код:** `scripts/db-publish.ts:130-148`, `src/app/admin/actions.ts:62-69`.

Админка сохраняет `price`, `priceWholesale`, `stockCount`, `inStock` непосредственно в production. Публикация удаляет все Product и вставляет полные локальные записи. Например: менеджер установил в production цену 150 и остаток 20, а локально остались 100 и 0. Следующая штатная публикация возвращает 100 и 0. Проверка количества строк не выявляет потерю этих правок. Заявки при этом не удаляются: проблема именно в коммерческих полях каталога.

**Подтверждение:** чтение обеих цепочек записи; публикация в production не выполнялась.

**Исправление:** определить владельца коммерческих полей и сохранять production-значения при обновлении описаний, либо вынести их в отдельную сущность. Приёмка: изменить цену/остаток в админке sandbox, опубликовать обновлённое описание и убедиться, что коммерческие значения сохранились.

### R4. P2 - спецсимволы ломают поиск

**Код:** `src/lib/queries/products.ts:260-266`; аналогичная сборка в `src/app/api/search/route.ts` и экспорте.

**Воспроизведено на публичном сайте:** `/catalog?q=%21%21` показывает «Ошибка загрузки каталога». Контрольный запрос `STM32F103C8T6` находит товар. После очистки токена от спецсимволов код безусловно добавляет `:*`; получается недопустимый tsquery. Проверка пустоты после этого уже не помогает. Автодополнение скрывает SQL-ошибку за успешным пустым ответом.

**Исправление:** единая сборка поискового выражения, удаление пустых токенов после очистки, ограничение длины/числа токенов, тесты `!!`, `()`, смешанного текста и маркировок со знаками. SQL-параметризация здесь есть; SQL injection этим случаем не доказана.

### R5. P2 - потеря сети навсегда блокирует отправку

**Код:** `src/app/request-quote/page.tsx:95-113`, `src/app/wholesale/page.tsx:101-113`.

**Воспроизведено:** открыть форму с товаром, заполнить синтетическими данными, отключить сеть в тестовом браузере и отправить. Кнопка остаётся disabled с текстом «Отправка...», сообщения об ошибке нет. `await submitQuoteRequest` бросает транспортную ошибку, поэтому сброс флага не выполняется. У оптовой формы тот же шаблон без `try/catch/finally`.

Сеть была выключена до отправки; тестовая заявка не отправлялась в production. Перед восстановлением сети заполненная страница была закрыта.

**Исправление:** обрабатывать транспортные исключения, всегда сбрасывать pending в `finally`, сохранять заполненный черновик для повторной попытки. Приёмка - восстановление сети без потери формы и возможность повторить отправку.

### R6. P2 - повтор одной заявки создаёт дубли

**Код:** `src/app/request-list/actions.ts:70-104`, `prisma/schema.prisma:248-274`; также `src/app/wholesale/actions.ts`.

Нет ключа идемпотентности и уникального ограничения для повтора отправки. Если сервер сохранил заявку, но ответ потерялся, после перезагрузки повтор создаёт новый номер и новое уведомление. Rate limit ограничивает частоту, но не устраняет дубли.

**Подтверждение:** исполнен реальный код action с подменёнными БД, лимитером и уведомлениями. Два одинаковых вызова дали две записи и разные ID. Production не изменялся.

**Исправление:** устойчивый ключ отправки в черновике и уникальность в БД; повтор возвращает прежний ID. Не использовать только время или глобальный хеш корзины, чтобы не запретить намеренный повторный заказ.

### R7. P2 - строки КП и общий итог используют разные цены

**Код:** `src/app/request-quote/page.tsx:390-404`, `src/hooks/use-cart.ts:104-108`.

**Воспроизведено в браузере на синтетической локальной корзине:** 10 штук, розничная цена 100, оптовая 80. Строка формы показывает `10 × 100 = 1 000 ₽`, общий итог `800 ₽`. Строки берут `product.price`, итог выбирает оптовую цену. В текущем каталоге оптовые цены отсутствуют, поэтому проявление ожидается после их заполнения. Изменён был только localStorage тестового браузера, затем исходная корзина восстановлена.

**Исправление:** единое правило выбора цены для карточки строки, корзины и формы; проверять равенство суммы строк итогу.

### R8. P2 - смешанная корзина выдаёт неполную сумму за общую

**Код:** `src/hooks/use-cart.ts:104-108`, `src/app/cart/page.tsx:234-245`.

**Воспроизведено на реальных товарах:** 2 × STM32F103C8T6 по 160 ₽ и 1 × AD1580ARTZ-REEL7 без цены. Итог озаглавлен «Сумма корзины: 320 ₽», без отметки, что одна позиция не учтена. Подсказка о неопределённой цене включается только при `totalPrice === 0`, поэтому смешанный случай пропущен.

**Исправление:** «Известная часть: 320 ₽ + 1 позиция по запросу» либо общий итог «По запросу» с отдельной известной частью. Сохранить такое же представление на оформлении.

### R9. P2 - главный CTA не позволяет отправить спецификацию

**Код:** `src/components/home/hero-slider.tsx:47-69`, `src/app/request-quote/page.tsx:148-173`.

Баннер обещает «Пришлите список MPN» и «Отправить список», но ведёт на `/request-quote`. Новый покупатель с пустой корзиной получает «Корзина пуста» и предложение искать в каталоге. Поля для списка, файла или отсутствующего в каталоге MPN в этом маршруте нет. Пустое состояние проверено в браузере.

**Исправление:** направить CTA на реальный ввод спецификации, например отдельную BOM-форму с MPN/количествами и нераспознанными позициями, либо назвать действие «Собрать корзину». Самостоятельный ввод отсутствующего товара особенно нужен при текущем малом каталоге.

### R10. P2 - ошибки уведомлений не доставляются повторно

**Код:** `src/lib/notifications.ts:42-63`, `src/app/request-list/actions.ts:106-133`, `prisma/schema.prisma`.

Ошибка Telegram преобразуется в `failed`, записывается в технический лог и забывается. Нет устойчивой очереди, сохранённого статуса доставки или задания повторной отправки. Покупатель получает успех, менеджер может не узнать о лиде, если работает по уведомлениям. Сама заявка в БД сохраняется: это потеря оповещения, не потеря записи.

**Подтверждение:** код и изолированная проба action с `notification.status='failed'`; внешние сообщения не отправлялись.

**Исправление:** запись задания уведомления вместе с заявкой, ограниченные повторы с задержкой, видимый менеджеру статус сбоя. Проверить сценарий «Telegram недоступен - восстановился - уведомление доставлено один раз».

### R11. P2 - старые лиды исчезают из доступной менеджеру выборки

**Код:** `src/app/admin/(panel)/wholesale/page.tsx:12-15`, `src/app/admin/(panel)/requests/page.tsx:14-19`.

Обе страницы ограничены последними 100 записями без пагинации. После появления следующей сотни часть необработанных лидов нельзя найти через список. У оптовых лидов дополнительно нет действия изменения статуса, хотя отображаются значения `new/in_progress/closed`. В action-файле админки есть изменение статуса только QuoteRequest.

**Исправление:** пагинация, поиск/фильтр необработанных лидов и защищённое обновление статуса WholesaleLead с соответствующими правами runtime-роли. Приёмка - доступ к самой ранней незакрытой записи при более чем 100 новых.

### R12. P2 - CSV-экспорт сохраняет формулы из внешнего каталога

**Код:** `src/app/api/catalog/export/route.ts:8-12`.

Экранирование обрабатывает кавычки и разделители, но не формульные префиксы `=`, `+`, `-`, `@` и управляющие символы. Изолированное выполнение функции подтверждает: `=1+1` остаётся `=1+1`. Если вредоносная строка из данных поставщика попадёт в наименование/производителя и CSV откроют в табличном редакторе, возможна интерпретация её как формулы. Обычный посетитель не получил этим возможность записывать каталог; путь угрозы проходит через входные данные поставщиков.

**Исправление:** безопасная текстовая сериализация ячеек, обработка CR и формульных префиксов, проверка экспорта в используемом Excel/LibreOffice. Не проверять на формулах с внешними сетевыми обращениями.

### R13. P2 - лимит размера изображения проверяется после полного скачивания

**Код:** `src/lib/storage/r2-client.ts:132-144`.

`MAX_BYTES = 8 MiB` не ограничивает чтение потока: сначала вызывается `resp.arrayBuffer()`, затем проверяется размер. Быстрый источник может прислать большой ответ и исчерпать память оператора раньше проверки; таймаут ограничивает время, но не байты. Это риск локального enrichment, а не доказанный публичный DoS витрины.

**Исправление:** предварительная проверка Content-Length и обязательный счётчик байтов при потоковом чтении с отменой по превышению. Проверять также переходы на непубличные адреса при скачивании внешних URL. Атака большим файлом в рамках ревью не выполнялась.

### R14. P2 - сервер не сверяет минимальную партию

**Код:** `src/app/request-list/actions.ts:53-55`, `src/lib/validate-quote-input.ts:109-119`.

Сервер проверяет существование товаров и целое количество от 1, но не загружает `minOrder`. Ограничение минимальной партии остаётся на клиенте. Изолированная проба: товар с `minOrder=100`, количество 1 - action сохраняет 1. В текущем live-каталоге минимальные партии больше 1 отсутствуют, поэтому это дефект перед включением оптовых ограничений. Проверка количества против склада для запроса КП не приравнивается к обязательному резервированию.

**Исправление:** сверять минимум с актуальным товаром на сервере; возвращать конкретную позицию и допустимое количество.

### R15. P2 - отдельные публичные страницы читают каталог без лимита

**Код:** `src/lib/queries/products.ts:101-115,140-165`, `src/app/best/page.tsx:12-13`, `src/app/popular/page.tsx:12-13`, `src/app/product/[slug]/page.tsx:43-44`.

`/best` и `/popular` загружают все товары со всеми изображениями, характеристиками и datasheet, затем берут 20 в памяти. Страница товара аналогично загружает всю категорию ради четырёх рекомендаций. Объём запроса растёт с каталогом независимо от размера отображаемой выдачи; при заявленных тысячах компонентов это риск задержек и нехватки памяти. На текущем малом наборе фактический отказ не воспроизводился, нагрузочный тест production не проводился.

**Исправление:** фильтры, исключение текущего товара, лимиты и нужные поля переносить в запрос к БД. Проверять на representative sandbox-каталоге.

## Дополнительные риски безопасности

- `xlsx@0.18.5` используется реальным локальным импортёром, хотя находится в devDependencies. Полный npm audit отмечает prototype pollution и ReDoS. Для исправления требуется отдельно выбрать поддерживаемую поставку SheetJS или заменить парсер: `npm audit fix` не предлагает исправления этого пакета. [Advisory ReDoS](https://github.com/advisories/GHSA-5pgg-2g8v-p4x9). Не выдавать это за удалённую загрузку XLSX на сайте: такого endpoint не найдено.
- csv-parse имеет advisory для пути `columns`; текущий импортёр получает массивы без этой опции. Уязвимая версия подтверждена, применимость указанного exploit-path в текущем вызове не подтверждена.
- `/admin/login` отдаётся без CSP/frame-ancestors и X-Frame-Options. Добавить запрет встраивания административных страниц. Практическая эксплуатация clickjacking с текущей SameSite-cookie не проверялась.
- Ключ rate limit выбирается из первого `x-forwarded-for`. Без гарантии нормализации заголовка доверенным ingress его можно подменять. На Vercel обход не воспроизведён; это проверка границы доверия перед self-hosted deployment, а не подтверждённая дыра текущего сайта.
- Все 14 public-таблиц имеют RLS, найдены 19 runtime-политик. У `anon`, `authenticated`, `electromagaz_app` нет superuser/BYPASSRLS. Политики заявок допускают текущего пользователя `electromagaz_app`, а не произвольного анонимного посетителя. Public SECURITY DEFINER функций не найдено. Advisors выдал только три INFO для намеренно закрытых служебных таблиц без политик: [описание проверки](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).
- У anon/authenticated остаются широкие табличные grants, но они сами по себе не обходят RLS. Проверка реального SELECT через SET ROLE оказалась недоступна текущему MCP-пользователю (`permission denied to set role`). Поэтому поведенческая проверка этих ролей остаётся открытой; вывод об отсутствии прямой утечки ограничен просмотренными grants/policies.

## Чего не хватает покупателю и оператору для запуска

1. **Один понятный продукт.** Текущий checkout, оферта и доставка ориентированы на юридические лица и ИП. Для B2B-запуска оплата по счёту допустима как выбранный процесс; онлайн-эквайринг не является самостоятельным техническим блокером. Для розницы текущая форма с обязательной компанией и ИНН непригодна. Формулировки «оптом и в розницу» в metadata каталога нужно согласовать с реальным процессом.
2. **Честный вход в отправку BOM.** Передача списка MPN/количеств, включая отсутствующие позиции, должна работать без предварительного поиска каждого товара в каталоге. Сейчас главный CTA приводит в пустую корзину (R9).
3. **Рабочая связь после заявки.** Покупателю нужен номер, сохранённая ссылка и подтверждение на email; менеджеру - очередь необработанных заявок и повтор уведомлений. Сейчас есть страница статуса и предложение вручную сохранить ссылку, но клиентская отправка подтверждения отсутствует. Нужен обещанный срок ответа и ответственный за него.
4. **Завершённый профиль либо отсутствие обещания профиля.** `/account` - явный макет: login/register только меняют текст, коды не отправляются, истории заказов нет (`src/app/account/account-client.tsx:127-155`). До реализации убрать активную имитацию входа из основного пути или заменить полезной страницей отслеживания заявки.
5. **Данные для принятия решения.** См. LIVE snapshot: цены заполнены лишь у небольшой части каталога, подтверждённых складских остатков нет.
