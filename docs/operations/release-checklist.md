остаётся `[ ]` с пояснением. Пункт отмечается `[x]` только после фактической
проверки результата.

## 1. До сборки

- [ ] `git status -sb` не содержит незнакомых изменений.
- [ ] Ветка создана от свежего `origin/main`.
- [ ] `git diff --check` проходит.
- [ ] В diff нет `.env`, credentials, логов, дампов БД и runtime artifacts.
- [ ] Изменения схемы оформлены отдельной Prisma migration.
- [ ] Для новой бизнес-логики обновлены профильные документы и план.
- [ ] Для опасных внешних операций подтверждены target и доступ.

## 2. Проверки кода

- [ ] `npm test`.
- [ ] `npm run test:integration`.
- [ ] `npm run lint`.
- [ ] `npm run build`.
- [ ] `npm run test:e2e` для desktop и mobile.
- [ ] Известные warnings перечислены и приняты владельцем либо исправлены.

## 3. База и данные

- [ ] Проверен `prisma migrate status` для нужного target.
- [ ] Migration SQL просмотрен вручную.
- [ ] В migration нет лишнего изменения generated `searchVector`.
- [ ] Создан или подтверждён актуальный backup.
- [ ] Известен и проверен способ восстановления.
- [ ] `db:publish` не затрагивает заявки и оптовые лиды.
- [ ] Для enrichment проверена первая строка входного файла.
- [ ] Перед реальным enrichment выполнен `--dry-run --limit 3`.
- [ ] Production migration или `db:publish` отдельно подтверждены владельцем.

## 4. Preview

Контрольные запросы текущего LIVE-каталога. После утверждения ассортимента
заменить или дополнить их ключевыми MPN владельца:

- `APM32F103C8T6`;
- `ADUC812`;
- `HMC908`.

- [ ] Vercel Preview относится к ожидаемому commit.
- [ ] Preview использует ожидаемые Environment Variables.
- [ ] Главная открывается без server error.
- [ ] Каталог открывается и сохраняет URL-параметры.
- [ ] Контрольные MPN находятся через поиск.
- [ ] Карточка товара открывается с изображением и документами.
- [ ] Корзина сохраняется после обновления страницы.
- [ ] Форма КП проходит тестовый сценарий на безопасной тестовой базе.
- [ ] Оптовая форма проходит тестовый сценарий на безопасной тестовой базе.
- [ ] Админка защищена и показывает созданные тестовые записи.
- [ ] `/legal`, `/offer`, `/privacy`, `/returns` и `/contacts` не содержат
      плейсхолдеров и тестовых контактов.
- [ ] Проверены desktop и mobile.
- [ ] Проверены keyboard navigation, loading, empty, error и success states.
- [ ] В браузерной консоли нет необъяснённых ошибок.

- [ ] Владелец принял Preview визуально и функционально.
- [ ] Pull Request получил review.
- [ ] Зафиксированы точные production migration и data operations.
- [ ] Зафиксировано окно выпуска.
- [ ] Назначен наблюдающий после выпуска.
- [ ] Rollback готов до начала production-операций.

## 6. Production release

- [ ] Pull Request слит в `main`.
- [ ] Production deployment относится к ожидаемому commit.
- [ ] Production migration применена и записана в `_prisma_migrations`.
- [ ] Если требовалось, каталог опубликован в правильную базу.
- [ ] `prisma migrate status` подтверждает актуальную схему.
- [ ] `npm run db:stats` возвращает ожидаемый LIVE-снимок.
- [ ] `npm run enrichment:status` не показывает незапланированный активный run.

## 7. Production smoke-test

- [ ] `electromagaz.ru` резолвится и открывается по HTTPS.
- [ ] Canonical URL указывает на основной домен.
- [ ] Главная, каталог, товар, корзина и сравнение отвечают без server error.
- [ ] Публичный API поиска возвращает контрольный товар.
- [ ] Тестовая заявка сохранена в Supabase.
- [ ] Telegram-уведомление получено.
- [ ] Email покупателю получен, если функция включена.
- [ ] Заявка доступна в админке и меняет статус.
- [ ] Публичный статус заявки открывается.
- [ ] Production-заявки, существовавшие до выпуска, сохранены.
- [ ] Robots и sitemap отвечают корректно.
- [ ] Uptime и error monitoring получают события.

## 8. Handoff

- [ ] Записаны ветка, commit, PR и deployment.
- [ ] Перечислены выполненные проверки.
- [ ] Перечислены пропущенные проверки и причины.
- [ ] Перечислены применённые миграции и data operations.
- [ ] Указан точный следующий шаг.
- [ ] Обновлены MVP-план и ретроспектива.

## Rollback

При критической ошибке:

1. Остановить новые migration, enrichment и publication operations.
2. Зафиксировать симптом, время и затронутый target.
3. Вернуть Vercel на заранее выбранный рабочий deployment.
4. Не откатывать БД вслепую. Использовать заранее проверенный forward fix или
   восстановление только после оценки новых production-данных.
5. Проверить основной пользовательский путь после восстановления.
6. Записать инцидент и добавить защиту от повторения.
