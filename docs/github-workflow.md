# GitHub workflow для Electromagaz

## Зачем нужны ветки

Ветка - изолированная линия работы. Она нужна, когда задача ещё не готова: редизайн, новая интеграция, рискованная миграция или эксперимент. В `main` остаётся рабочая версия, а в ветке можно безопасно делать серию коммитов, проверять их и смотреть preview.

Текущая история DNS-редизайна перенесена в `main`, потому что это стартовая история нового private-репозитория. Для следующей незавершённой задачи создавай новую ветку от свежего `main`.

```bash
git switch main
git pull --ff-only
git switch -c feat/короткое-название-задачи
```

## Обычный цикл

1. Одна понятная задача - одна ветка.
2. Делай маленькие осмысленные коммиты: `feat`, `fix`, `docs`, `test`, `chore`.
3. Перед push запускай подходящие проверки.
4. Добавляй файлы поимённо: `git add src/нужный-файл.ts`. Не используй `git add .`.
5. Пушь ветку и открывай Pull Request в `main`, если нужен review, preview или безопасное слияние.
6. После merge удали ветку и начни следующую задачу от свежего `main`.

## Что не класть в Git

Private-репозиторий не является сейфом для секретов. Не коммить `.env*`, API-ключи, токены, пароли, локальные database dumps, логи, `node_modules`, кэши и generated output. Для восстанавливаемых локальных данных держи отдельный зашифрованный backup с проверенным доступом.

## Текущее правило хранения

В этом репозитории versioned: код, второй мозг, планы, ретроспективы, инструкции агентов и доступные материалы parser/collector. Локальный `config.yaml` остаётся вне Git, поскольку он может содержать credentials. Последний исходный код удалённого collector восстановлен из истории в `tools/collector-legacy`; перед production-использованием он требует отдельного аудита.
