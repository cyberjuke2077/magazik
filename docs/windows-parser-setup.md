# Массовый parser/enrichment на Windows

Эта инструкция запускает актуальный TypeScript pipeline из `src/lib/enrichment`.
Архивный `tools/collector-legacy` не используется.

## Что реально делает запуск

- читает CSV, XLS и XLSX с MPN и необязательным производителем;
- нормализует и дедуплицирует позиции;
- последовательно использует ChipDip, LCSC и настроенный Mouser;
- пишет карточки и журнал только в локальную PostgreSQL на Windows;
- сохраняет найденные URL картинок и PDF как `pending`-кандидаты;
- не пишет в production Supabase, R2 и не запускает `db:publish`.

Полный проход означает, что каждая позиция получит терминальный статус. Это не
означает, что каждый MPN обязательно будет найден. Позиции, которых нет во всех
доступных источниках, останутся `unresolved` и будут видны в меню.

## 1. Подготовить Windows

1. Установите GitHub Desktop и клонируйте private-репозиторий
   `cyberjuke2077/magazik` в простую папку, например `C:\electromagaz`.
2. В проводнике откройте папку `windows`.
3. Дважды нажмите `INSTALL.cmd`.
4. Установщик через `winget` поставит Node.js LTS и Docker Desktop, если их нет.
5. Если установщик попросит перезагрузку, перезагрузите Windows, откройте Docker
   Desktop, дождитесь `Engine running` и снова запустите `INSTALL.cmd`.
6. Установщик создаст локальный `.env`, выполнит `npm ci`, запустит PostgreSQL и
   применит миграции. `.env` не отправлять в чат и не добавлять в Git.

## 2. Скопировать полный список

Приватные файлы заказчика не хранятся в репозитории. Скопируйте все 11 исходных
CSV/XLS/XLSX в отдельную папку на Windows. Не смешивайте их с `data/parsed`.

Ранее подтверждённый контрольный результат полного набора:

- файлов - 11;
- строк - 75 706;
- пропущено строк - 17;
- уникальных MPN - 67 200.

Это старый подтверждённый snapshot, а не текущая проверка файлов на этой
машине. Перед live-запуском цифры нужно получить заново через dry-run.

## 3. Проверить вход без интернета и БД

1. Дважды нажмите `RUN-PARSER.cmd`.
2. Выберите папку с 11 файлами.
3. Выберите `1 - Validate all files offline`.
4. Сверьте четыре числа выше.

Dry-run заканчивается до PostgreSQL и внешних источников. Если цифры отличаются,
не запускайте live-проход: проверьте папку и состав файлов.

## 4. Выполнить пилоты

1. Выберите пункт `2` для одного товара.
2. Проверьте статус и сохранённую карточку.
3. Выберите пункт `3` для пяти товаров.
4. Пункт `7` показывает текущий run, прогресс и статусы локальной базы.
5. Пункт `8` показывает позиции `unresolved`.

Пилоты используют `--force-refresh`. Полный запуск потом пропустит свежие
успешные карточки и продолжит по остальному списку.

## 5. Запустить весь остаток

1. Выберите пункт `5`.
2. Введите точную фразу `RUN ALL`.
3. Не закрывайте Docker Desktop.
4. Launcher блокирует автоматический сон Windows, пока дочерний parser работает.
5. Экран можно заблокировать, но нельзя выключать или перезагружать компьютер.

При блокировке одного источника pipeline переводит позиции в следующий источник,
а не зависает на многочасовой паузе. Если ключ Mouser не настроен, после LCSC
позиция завершится как `unresolved`.

При контрольном объёме 67 200 MPN и штатной задержке ChipDip 30-60 секунд только
паузы первого источника занимают примерно 23-47 суток. Загрузка страниц и
fallback-источники увеличивают срок. Не рассчитывайте закончить полный run за
одну ночь.

## 6. Остановка и продолжение

- Нажмите `q`, чтобы сохранить текущий результат, закрыть браузеры и завершить
  процесс с кодом безопасной остановки.
- После перезапуска откройте `RUN-PARSER.cmd`, выберите ту же входную папку и
  пункт `6 - Resume interrupted run`.
- Resume выбирает только последний run со статусом `running` или `paused` и без
  `completedAt`. Если такого run нет, launcher покажет явную ошибку и не создаст
  пустой журнал.
- Resume работает по существующему журналу и не отбрасывает незавершённые позиции
  из-за freshness-фильтра.

## 7. Что считать завершением

Пункт `7` должен показать нулевой остаток активной очереди. Итог разбивается на:

- `chipdip_done`, `lcsc_done`, `mouser_done` - карточка найдена;
- `mouser_not_found`, `mouser_failed`, `mouser_brand_mismatch`, `unresolved` -
  позиция обработана, но готовая карточка не получена;
- промежуточные `pending`, `chipdip_not_found`, `chipdip_blocked`,
  `lcsc_not_found`, `lcsc_blocked`, `mouser_queued` - run ещё не закончен.

Публикация локального результата в production выполняется отдельной задачей
только после проверки количества карточек, unresolved и выборочной ручной
проверки данных.
