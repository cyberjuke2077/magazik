# Адверсариальное ревью - 2026-09-17

## Задача

Проверить ошибки кода, безопасность и готовность магазина к коммерческому запуску с позиции покупателя.

## Как решали

Сверили commit с GitHub main, изучили обработку заявок, админку, поиск, корзину, импорт и публикацию. Прошли публичный путь покупателя в отдельной BrowserAct-сессии. Проверили зависимости через npm audit и advisory разработчиков, Supabase target/регион/grants/RLS через read-only MCP. Для повтора заявок, minOrder и CSV исполнили реальный код с изолированными подменами БД и внешних интеграций.

## Результат

Ревью завершено: [отчёт с 15 находками и критериями исправления](../docs/operations/adversarial-review-2026-09-17.md). Приложение не исправлялось. Пройдены 307 unit-тестов, lint и TypeScript. Обнаружены три P1: уязвимые Next.js/sharp, противоречие политики ПДн фактическому региону, стирание production-цен и остатков локальной публикацией.

Проверенный исходный commit: `2bd5d94480eb24e359a0bba10c232699ab5b88b5`. Ветка отчёта: `codex/adversarial-review-20260917`. Push и deployment не выполнялись. Первый следующий шаг - обновление уязвимых зависимостей с проверками и отдельное решение владельца о размещении ПДн.

## Что можно было лучше

Для смены viewport была запрошена CDP capability-ссылка. Automatic approval review отклонил доступ как более широкий, чем мобильная проверка. Запрет не обходился, мобильная проверка явно осталась за границей отчёта. Проверку SET ROLE текущий Supabase MCP тоже не разрешил; результаты просмотра политик не выданы за поведенческий тест ролей.

## Изменения во втором мозге

Добавлен отчёт и свежий агрегированный snapshot каталога в live-metrics.md. Глобальная память Codex не изменялась. Бизнес-решения не принимались, ограничения запуска помечены в отчёте как требующие решения.

Предложение, не применённое к AGENTS.md: `Rule: Перед публичным релизом проверять актуальные advisory для production-зависимостей и повтор отправки заявки после потери ответа. | Why: 307 зелёных тестов не выявили уязвимые зависимости и дублирование лидов.`

## Продолжение: исправления по разрешению владельца

После запроса «начинай исправление всего что можешь» выполнены локальные исправления 14 находок, R2 закрыта частично. Итоговая реализация, commits, проверки и открытые условия запуска: [readiness-fixes-2026-09-17.md](../docs/operations/readiness-fixes-2026-09-17.md). Предыдущие абзацы описывают этап ревью до изменений.

Проверки: 330 unit, 5 интеграционных и 16 браузерных тестов на собранном приложении; TypeScript, lint и build успешны. Для миграции и атакующих сценариев использовалась отдельная PostgreSQL 16 с синтетическими данными. Реальный Telegram отключён. Проверена мобильная версия через самостоятельный локальный Chromium без доступа к CDP или пользовательским браузерным профилям. RLS проверена поведением ролей только на локальной базе.

Рабочая ветка остаётся `codex/adversarial-review-20260917`; push/deploy и production migrations не выполнялись. Первое внешнее действие требует решения о размещении ПДн и согласованного порядка миграции/выкладки. Фактические сроки обработки, почта и инфраструктура не выдумывались.

Уточнения процесса: первый запуск браузерных тестов потерял `--grep` во вложенном npm-скрипте; исправлен разделитель аргументов, затем проверено число реально исполненных тестов. Один локальный запрос миграции ссылался на предполагаемый путь; найден реальный файл, повтор выполнен на той же изолированной БД. Код и документы проверены по фактическим результатам, не по статусу «запущено».

Второй мозг обновлён в product.md, architecture.md, ru-market-launch.md и INDEX.md; прежний адрес production и утверждение о тысячах опубликованных позиций заменены подтверждённым адресом и ссылкой на LIVE. Глобальная память не менялась.
