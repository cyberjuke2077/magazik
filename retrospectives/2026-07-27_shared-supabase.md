# Общая Supabase БД команды

## 1. Задача

Создать общую облачную PostgreSQL БД для команды Electromagaz, применить к ней
схему Prisma и выдать соразработчику персональный доступ.

## 2. Как решали

Создали отдельный Supabase-проект в `37Lunar's Org`, пригласили
соразработчика с ролью `Developer` и применили миграции Prisma. По отчёту
разработчика, RLS для таблиц включён. Текущая рабочая копия разработчика
подключена к общей БД через Session Pooler в локальном `.env`.

## 3. Результат

Частично подтверждено. Разработчик зафиксировал семь применённых миграций,
двенадцать таблиц приложения и включённый RLS. Строки подключения и пароль не
попали в Git. Независимая live-проверка этой базы из текущей Codex-авторизации
не выполнена: она пока не видит `37Lunar's Org`.

## 4. Что можно было лучше

Перед переключением рабочих копий нужно заранее подготовить версионируемую
инструкцию подключения без секретов и согласовать границу между общей средой
интеграции и production.

## 5. Изменения во втором мозге

В архитектуру и onboarding добавлены правила общей Supabase БД: персональные
приглашения, роль `Developer`, локальные `.env` и отдельное подтверждение
production-настроек.
