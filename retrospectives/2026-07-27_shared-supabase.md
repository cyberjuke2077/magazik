# Общая Supabase БД команды

## 1. Задача

Создать общую облачную PostgreSQL БД для команды Electromagaz, применить к ней
схему Prisma и выдать соразработчику персональный доступ.

## 2. Как решали

Создали отдельный Supabase-проект `37Lunar's Project` в `37Lunar's Org`,
пригласили соразработчика с ролью `Developer` и применили миграции Prisma.
Текущая рабочая копия разработчика подключена к общей БД через Session Pooler
в локальном `.env`.

## 3. Результат

Подтверждено read-only проверкой Supabase Dashboard 2026-07-31. Проверен проект
`37Lunar's Project` с ref `dbumwpnbtvixfusxnggn`: в `public` есть двенадцать
таблиц приложения и `_prisma_migrations`, все семь локальных миграций отмечены
как завершённые. В каталоге сейчас 3 товара, 9 категорий, 5 производителей,
10 изображений и 19 спецификаций. Клиентские заявки отсутствуют.

RLS включён на всех двенадцати таблицах приложения и на
`_prisma_migrations`, политик нет. Security Advisor показывает 0 ошибок,
0 предупреждений и 13 информационных рекомендаций `RLS Enabled No Policy`.
Это закрывает прямой Data API для ролей `anon` и `authenticated`; серверный
Prisma продолжает работать через PostgreSQL-подключение. Supabase Dashboard
также показывает `No repository connected`, поэтому GitHub-репозиторий и
Supabase-проект пока не связаны встроенной интеграцией Supabase.

Строки подключения и пароль не попали в Git. Supabase MCP текущего Codex-сеанса
не имеет доступа к новой организации, поэтому live-проверка выполнена через
авторизованный Dashboard без изменения БД.

## 4. Что можно было лучше

Перед переключением рабочих копий нужно заранее подготовить версионируемую
инструкцию подключения без секретов и согласовать границу между общей средой
интеграции и production. Если приложению понадобится прямой Supabase Data API,
нужно отдельно спроектировать минимальные RLS-политики. Не добавлять политики
только ради удаления информационных рекомендаций Advisor.

## 5. Изменения во втором мозге

В архитектуру и onboarding добавлены правила общей Supabase БД: персональные
приглашения, роль `Developer`, локальные `.env` и отдельное подтверждение
production-настроек.
