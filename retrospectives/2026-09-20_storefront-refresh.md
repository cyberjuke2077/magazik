# Обновление витрины и подготовка наполнения, 2026-09-20

## Приёмка и подготовка push/merge

Владелец принял компактную главную и запросил push/merge. Девять PNG с его
отдельного разрешения опубликованы в R2 под новыми ключами с SHA-256 в именах;
публичные ответы проверены побайтно. Код `37cba51` использует R2 URL, изображения
не добавлены в Git. 420 unit, 34 storefront E2E, два повторных визуальных теста
через R2, TypeScript, ESLint и webpack build прошли.

Read-only проверка production выявила прежние девять миграций: три необходимые
старым исправлениям ветки отсутствуют. Владельцу отправлен выбор объёма merge.
R2 сначала был заблокирован автоматической проверкой из-за «только локально»;
после явного разрешения загрузка завершена. Обхода блокировки не было.
Нельзя автоматически считать разрешение merge приёмкой production-зависимостей.

## Задача

Пользователь разрешил push накопленных изменений, запросил современный дизайн
по DNS с gptTASTE и начало наполнения товарной базы.

## Как решали

Проверили живой origin/main, отправили накопленную ветку после lint и webpack
build. Прочитали pipeline и Windows-инструкцию. Для UI использовали отдельную
локальную БД emg_readiness на 127.0.0.1:55434, уведомления отключены. DNS при
новом открытии вернул 403; прямой live-аудит референса не состоялся.
Редизайн выполнен на существующих компонентах и локальных изображениях.

## Что можно было лучше

Сразу учитывать containing block fixed-навигации при добавлении backdrop-filter.
Первый E2E нашёл потерю фокуса и overflow на 320 px, исправлено до фиксации.
При изменении DOM сразу обновлять селекторы тестов, сохраняя проверяемый сценарий.
При проверке SSR без JavaScript учитывать скрытый streamed HTML Next.js:
role locator без includeHidden не найдёт ещё не показанные кнопки.
