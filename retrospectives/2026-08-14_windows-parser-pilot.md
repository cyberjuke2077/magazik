# Windows parser pilot

## 1. Задача

Проверить enrichment-парсер на файлах заказчика, привести Ink TUI в рабочее
состояние и подготовить запуск на чистой Windows без ручного набора команд.

## 2. Как решали

- Исправили подписку TUI на состояние, реальные размеры очереди и русские
  подписи.
- Перевели CLI на ESM-entrypoint для совместимости Ink/Yoga с top-level await.
- Сделали безопасное завершение `q`/`Ctrl+C`, автоматический unmount и чистый
  экран без служебных логов.
- Выполнили dry-run всех 11 входных файлов и три живых ChipDip-прохода.
- После появления дубля `AD1940YSTZRL` исправили приоритет производителя и
  добавили alias `AD1` -> `Analog Devices`.
- Добавили Windows installer, launcher, русское меню и пошаговую инструкцию.
- Изолировали записи shutdown-интеграции test-prefix-ом и добавили cleanup.

## 3. Результат: частично

Код парсера, TUI и локальная запись карточек подтверждены на Mac. Unit-тесты:
289/289. Интеграционные shutdown-тесты: 7/7. Lint, TypeScript и production build
через webpack прошли. Dry-run подтвердил 67 200 уникальных MPN.

Код parser/TUI зафиксирован в `ab406c9`, Windows launcher - в `4e056f4`.

Физический запуск `INSTALL.cmd` и `RUN-PARSER.cmd` на чистой Windows ещё не
выполнен. Массовый прогон и image worker не запускались. Production Supabase и
R2 не изменялись.

Обычный Turbopack build в среде Codex дважды упёрся в запрет создания локального
служебного порта. Штатный `next build --webpack` прошёл полностью. Это
ограничение среды проверки, а не подтверждённая ошибка приложения.

## 4. Что можно было лучше

- Сразу проверить ESM-совместимость Ink, а не полагаться на fallback.
- До первого `psql` прочитать фактический `POSTGRES_USER`.
- Сразу дать интеграционным run уникальный prefix, чтобы тесты не загрязняли
  локальную очередь resume.
- Не считать source-brand более надёжным, чем бренд из файла заказчика.
- Не использовать специальную zsh-переменную `path` в проверочных циклах.

## 5. Изменения во втором мозге

- Архитектура теперь фиксирует Windows launcher и приоритет бренда заказчика.
- Добавлены правила проверки локальной DB identity, очистки integration-state и
  безопасных имён shell-переменных.
- Инструкция для Windows находится в `docs/windows-parser-setup.md`.
