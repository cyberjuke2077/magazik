# Аудит GitHub и Supabase после работы соразработчика

## 1. Задача

Проверить, действительно ли новая версия проекта находится на GitHub, безопасно сравнить её с локальной копией и подтвердить состояние облачной Supabase без изменения данных и схемы.

## 2. Как решали

- Получили свежие remote refs и сравнили `main` с ветками соразработчика.
- Проверили граф коммитов, состав изменений и служебные ссылки Pull Request.
- В отдельном временном checkout запустили unit-тесты и lint для ветки `codex/parser-trial-limit`.
- Production-сборку проверили на том же коммите в основном checkout и вернули локальную копию на `main`.
- Через Supabase выполнили read-only проверку единственного проекта, доступного текущей авторизации. После уточнения пользователя отдельно сверили организацию этого проекта с целевой организацией разработчика.
- Создали `codex/integrate-37lunar-work` от свежего `origin/main`, перенесли код и полезные документы соразработчика, исключили пустой коммит `тест` и вручную объединили конфликтующие разделы архитектуры.
- Повторно выполнили unit-тесты, lint и production build на итоговой интеграционной ветке.

## 3. Результат: да

- Pull Request #2 с веткой `codex/integrate-37lunar-work` влит в `main`. Локальный `main` и `origin/main` совпадают на merge-коммите `c03986e`.
- Кодовая ветка `codex/parser-trial-limit` находится на `cc6d459`. Она прошла 212 unit-тестов, lint без ошибок и production-сборку.
- Отдельная ветка `codex/test-commit` находится на `04a95af` и содержит документацию общей Supabase. Ветка расходится с кодовой веткой и представлена отдельным Pull Request.
- Итоговый `main` повторно прошёл 212 unit-тестов, lint с 0 ошибок и 11 существующими предупреждениями, а также production build.
- Supabase-авторизация получила доступ к `37Lunar's Org`, а пользователь получил роль Administrator. Подтверждён проект `37Lunar's Project` с ref `dbumwpnbtvixfusxnggn`.
- Проект Supabase подключён к `cyberjuke2077/magazik`: working directory `.`, автоматический production deploy выключен, automatic branching выключен. После перезагрузки страницы настройка подтверждена кнопкой `Disable integration`.
- Ветка `codex/minimal-ui-redesign` содержит три коммита, но последний коммит откатывает редизайн. Итоговое дерево этой ветки совпадает с `origin/main`, поэтому переносить из неё нечего.
- В проекте `cyberjuke2077's Org/electromagaz` RLS выключен на всех 13 таблицах `public`, RLS-политик 0, роли `anon` и `authenticated` имеют права `SELECT`, `INSERT`, `UPDATE`, `DELETE`, `TRUNCATE`, `REFERENCES` и `TRIGGER` на все 13 таблиц.
- В Pull Request #2 перенесены осмысленные изменения соразработчика; пустой `a48e596 тест` не перенесён.
- Реальный integration-тест ChipDip не запускался, потому что он делает внешние запросы, а предыдущий health-check уже зафиксировал блокировку и остановку повторных запросов.
- Supabase-схема и данные не изменялись. Схема, миграции и RLS проекта `dbumwpnbtvixfusxnggn` в этой сессии не проверялись.

## 4. Что можно было лучше

До аудита нужно было сначала сверить organization и project ref, а уже затем запускать advisors и проверять `pg_policies`. При secret scan первая сложная shell-регулярка сломалась на кавычках; повторная проверка использовала отдельные `-e` паттерны по существующему правилу `secret-scan-shell-quoting`. В интерфейсе Supabase первый ответ при включении интеграции сообщил `Default branch already exists: main`, но перезагрузка показала, что подключение уже было сохранено. После мутации нужно было сразу проверять сохранённое состояние перезагрузкой, а не повторять действие.

## 5. Изменения во втором мозге

Добавлено правило `verify-live-supabase-security`: до проверки безопасности Supabase обязательно сверять organization, project ref и назначение среды. Архитектура и onboarding объединены с явным разделением integration и production. Исправление RLS и прав не выполнялось. Зафиксированы финальный merge в `main`, доступ к `37Lunar's Org` и безопасное подключение GitHub без автоматического применения миграций в production.
