# Закрытие release-хвостов

## Задача

Закончить зависимости всей ветки и согласованный выпуск после явного подтверждения владельца.

## Как решали

Сохранили и восстановили production public backup в изолированной PostgreSQL 17.
Исправили лишний ALTER ROLE, который запрещён managed PostgreSQL; повторили
репетицию без SUPERUSER/BYPASSRLS. Применили три миграции и проверили runtime
с rollback. Настроили Vercel env, Vault и выключенный Supabase cron. После
зелёного CI слили PR #26 и проверили deployment SHA, сайт и admin login/logout.

## Результат

Частично: технический выпуск `ae1f732` выполнен, production READY.
Scheduler выключен, тестовое сообщение не отправлено: автоматическая проверка
потребовала уточнения разрешения на обработку реальных заявок очередью.
Уточнение запрошено; ответ пока не получен. Точный статус в release closeout.

## Что можно было лучше

- Миграцию следовало сразу репетировать под ролью с production-правами.
- Проверка пустого drain всё равно имеет эффект отправки при конкурентной
  заявке; это нужно включать в описание разрешаемой операции.
- Для базовой logout-проверки достаточно удаления сессии и закрытия страницы.
  Экспорт cookie для replay-теста отклонён; replay остаётся непроверенным.

## Изменения во втором мозге

Добавлены release closeout и правило репетиции миграций с правами target.
Обновлены INDEX, цели, продукт, архитектура, реестр сервисов и план выпуска.
Прежние handoff помечены историей. Production backup, secrets, CLI state и
логи остаются вне Git. Глобальная память Codex не изменялась.
