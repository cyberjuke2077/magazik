# Упрощение главной, каталога и профиля

## 1. Задача

Убрать лишние товарные и рекламные блоки с главной, отказаться от кривого
мегаменю и промежуточной витрины каталога, вернуть точку входа в личный кабинет
и зафиксировать следующие этапы cookie-истории и реальной авторизации.

## 2. Как решали

- Сохранили query, storage, корзину, сравнение и server action контракты.
- Удалили две статические товарные полки и отдельный MPN-баннер с главной.
- Остановили автопрокрутку брендов, осветлили и увеличили фотомодули.
- По финальному уточнению владельца убрали карточку и упоминание `Честного ЗНАКА`,
  а бренды вернули в одну длинную статичную строку.
- Полностью удалили состояние, API-fetch и DOM мегаменю из `StickyNav`.
- Направили `/catalog` сразу в рабочий товарный листинг с деревом категорий.
- Создали `/account` как безопасную UI-оболочку без отправки и хранения ПДн.
- Проверили desktop и mobile в локальном браузере, включая overflow и консоль.

## 3. Результат: да для текущего прохода, редизайн продолжается

- Все семь правок владельца реализованы.
- Главная показывает только реальные недавно просмотренные товары.
- Каталог открывается одним переходом без всплывающего и промежуточного экранов.
- Профиль доступен из desktop и mobile навигации.
- Hero и шесть тематических фотомодулей имеют высоту 250 px на desktop.
- Двенадцать брендов находятся в одном ряду без CSS-анимации.
- TypeScript, `git diff --check`, lint, 199 unit-тестов и production build проходят.
- Lint оставляет 11 существующих предупреждений вне редизайна.
- Ветка `codex/dns-storefront-redesign` отправлена на GitHub до `6abcc0f`.
- По прямому уточнению владельца этот push является промежуточной контрольной
  точкой и не закрывает редизайн.

## 4. Что можно было лучше

- Сразу патчить повторяющиеся JSX-секции по уникальному заголовку.
- Не переобъявлять top-level bindings в persistent node_repl.
- Проверять фактический API браузерной обертки перед переносом helper-вызовов.
