# Очередь кандидатов медиа enrichment

## 1. Задача

Продолжить разбиение конфликтующего draft PR #13 и перенести минимальный
безопасный срез media/datasheet без Python worker, R2 upload и Windows launcher.

## 2. Как решали

- Сверили текущий `main` и точные старые diff для изображений и datasheet.
- Удалили сетевую загрузку и R2 upload из `persistBatch`.
- Добавили нормализацию, дедупликацию, лимиты и приоритет источников для URL.
- Сохраняем кандидатов и состояние `pending` в `Product.enrichmentMeta`.
- Не удаляем и не заменяем существующие строки `ProductImage` и `Datasheet`.
- Добавили тест границы persistence и unit-тесты очередей кандидатов.

## 3. Результат: частично

Безопасная граница сбора и публикации медиа реализована. Parser/enrichment
теперь только ставит URL в очередь и не выполняет скрытые R2-операции. Worker,
который проверяет файлы, очищает изображения, загружает результат в R2 и только
после успеха заменяет публичные строки, ещё не перенесён.

## 4. Что можно было лучше

Старый draft смешивал сбор URL, Python-обработку, запись в R2 и платформенные
launcher-файлы. Такие изменения нужно сразу делить по границам внешних эффектов:
сбор кандидатов, проверка файлов, upload, публикация в БД.

## 5. Изменения во втором мозге

- В архитектуре зафиксирована очередь кандидатов в `Product.enrichmentMeta`.
- Зафиксирован запрет прямой публикации upstream URL из persistence.
- Зафиксировано сохранение текущих публичных медиа до успешной замены worker.
- План PR #13 переведён к отдельному срезу image/datasheet workers и R2 upload.
