## Стиль кода

### Общие правила

- Пиши чистый, читаемый код — предпочитай ясность краткости
- Одна ответственность на функцию/модуль
- Не оставляй закомментированный код в PR
- Удаляй неиспользуемые импорты и переменные

### Именование

| Что              | Стиль         | Пример                  |
|------------------|---------------|-------------------------|
| Переменные       | camelCase     | `userName`              |
| Функции          | camelCase     | `getUserById()`         |
| Классы           | PascalCase    | `UserService`           |
| Константы        | UPPER_SNAKE   | `MAX_RETRY_COUNT`       |
| Файлы/папки      | kebab-case    | `user-service.ts`       |
| Компоненты (UI)  | PascalCase    | `UserCard.tsx`          |
| Типы/Интерфейсы  | PascalCase    | `UserProfile`           |

### Импорты

- Сначала внешние библиотеки, затем внутренние модули
- Группируй импорты: 1) сторонние, 2) алиасы проекта, 3) относительные
- Используй абсолютные импорты через алиасы (например `@/components/...`)

```ts
// ✅ Правильно
import { useState } from 'react'
import { Button } from '@/components/ui'
import { formatDate } from './utils'

// ❌ Неправильно
import { formatDate } from './utils'
import { useState } from 'react'
```

### Типизация

- Всегда указывай типы для аргументов функций и возвращаемых значений
- Избегай `any` — используй `unknown` если тип неизвестен
- Предпочитай `interface` для объектов, `type` для union/intersection

```ts
// ✅ Правильно
function getUser(id: string): Promise<User> { ... }

// ❌ Неправильно
function getUser(id): any { ... }
```

### Обработка ошибок

- Всегда обрабатывай ошибки явно — не глотай исключения
- Используй try/catch для async-операций
- Логируй ошибки с контекстом (что делали, какие данные)

```ts
// ✅ Правильно
try {
  const user = await fetchUser(id)
} catch (error) {
  console.error('Failed to fetch user', { id, error })
  throw error
}

// ❌ Неправильно
try {
  const user = await fetchUser(id)
} catch (e) {}
```

### Форматирование

- Отступы: **2 пробела**
- Кавычки: **одинарные** `'` (если нет конфига Prettier)
- Точка с запятой: по конфигу проекта
- Максимальная длина строки: **100 символов**
- Пустая строка в конце файла

## Работа с Git

### Ветки

```
main          — продакшн, прямые коммиты запрещены
develop       — основная ветка разработки
feature/...   — новая функциональность
fix/...       — исправление багов
chore/...     — рутинные задачи (зависимости, конфиги)
```

### Коммиты (Conventional Commits)

```
feat: добавить авторизацию через Google
fix: исправить падение при пустом массиве
chore: обновить зависимости
refactor: вынести логику в хук useAuth
docs: обновить README
test: добавить тесты для UserService
```

## Правила для AI-агентов

1. **Не меняй** файлы вне области задачи без явного запроса
2. **Не удаляй** существующие тесты
3. **Проверяй** что новый код покрыт тестами
4. **Следуй** стилю кода, уже существующему в файле
5. **Не коммить** `.env`, секреты, credentials
6. **Спрашивай** если задача неоднозначна — не угадывай
7. **Один PR** — одна задача, не смешивай несвязанные изменения
