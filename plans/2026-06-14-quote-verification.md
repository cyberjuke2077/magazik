# План: верификация заявки + подтверждение заказа (SMS + email + ИНН)

Дата: 2026-06-14
Связано: `plans/2026-06-14-ru-market-launch.md` (новая приоритетная фича)
Юр-тексты согласия/политики: `plans/2026-06-14-pdn-verification-draft.md` (готовит субагент)

## Зачем

Аудитория только B2B (физлиц нет). После создания заявки покупатель должен
подтвердить её, а система — проверить реальность контрагента. Цели:
1. **Double opt-in** — явное согласие заказчика с составом заявки.
2. **Проверка телефона** (SMS-код) — отсечь ботов и левые номера.
3. **Проверка контрагента по ИНН** (ЕГРЮЛ) — подтвердить, что заказчик реальная
   организация. Важно для контроля оборота электронных компонентов (часть —
   двойного назначения): «кто угодно не должен заказывать что угодно».

Только подтверждённая заявка уходит менеджеру (в админку + Telegram).

## Поток (статусы заявки)

Сейчас: заявка создаётся сразу в `new` и сразу видна менеджеру.

Станет:
```
[форма отправлена]
   → awaiting_confirmation   (создана, ждёт SMS-кода; менеджеру НЕ видна)
        │  параллельно: авто-проверка ИНН в ЕГРЮЛ → innCheck = ok|mismatch|not_found
   → [покупатель ввёл код]
   → confirmed               (телефон подтверждён, согласие зафиксировано)
        │  если innCheck != ok → флаг для ручной проверки менеджером
   → new                     (попадает менеджеру; дальше как сейчас)
   → in_progress → quoted → rejected
```
`awaiting_confirmation` с истёкшим кодом и без подтверждения через N часов →
авто-`expired` (чистка).

## Изменения схемы БД (миграция)

`QuoteRequest` — добавить:
- `phoneVerifiedAt DateTime?` — момент подтверждения телефона
- `emailVerifiedAt DateTime?` — опционально, если делаем double opt-in и по email
- `innCheckStatus String?` — `ok | mismatch | not_found | skipped`
- `innCheckData Json?` — снимок ответа ЕГРЮЛ (название, статус, адрес, дата)
- статусы расширить: `awaiting_confirmation, confirmed, expired` + текущие
- `contactPosition String?` — должность представителя (для согласия ПДн)

Коды подтверждения — отдельная таблица (не светить в QuoteRequest):
```
model VerificationCode {
  id             String   @id @default(cuid())
  quoteRequestId String
  channel        String   // sms | email
  codeHash       String   // sha256(code + secret), НЕ открытый код
  expiresAt      DateTime
  attempts       Int      @default(0)   // попытки ввода
  consumedAt     DateTime?
  createdAt      DateTime @default(now())
  @@index([quoteRequestId])
}
```

## Внешние провайдеры (выбрать, нужны ключи/договор/бюджет)

| Назначение | Кандидаты | Заметка |
|---|---|---|
| SMS | SMSC.ru, MTS Exolve, SMS Aero, P1SMS | Twilio в РФ не годится. Нужно имя отправителя (регистрация) |
| Email | Unisender Go, Sendsay, SMTP Яндекс 360 | Зарубежные (Resend/Postmark) хуже доставляются в .ru |
| Проверка ИНН | DaData.ru (есть free-тир), Контур.Фокус, ФНС egrul | DaData — простой API, рекомендуется для старта |

Все ключи — через env, не хардкодить. Абстрагировать за интерфейсы
(`SmsProvider`, `MailProvider`, `CounterpartyChecker`), чтобы провайдер менялся.

## Server actions / API

- `submitQuoteRequest` (есть) — изменить: создавать в `awaiting_confirmation`,
  генерировать код, слать SMS+email, запускать проверку ИНН (фоном). НЕ слать
  менеджеру/Telegram на этом шаге.
- `confirmQuoteRequest(quoteId, code)` — проверка кода (хэш, expiry, попытки,
  rate-limit), при успехе → `confirmed`/`new`, уведомление менеджеру + Telegram.
- `resendVerificationCode(quoteId)` — повторная отправка с rate-limit.
- Страница `/request-quote/confirm/[id]` — ввод кода, показ позиций, кнопка
  «Подтвердить заказ». Доступ по уникальной ссылке (id = cuid, без логина).

## Безопасность (критично — SMS стоит денег)

- Код 6 цифр, TTL 5-10 мин, хранить только хэш.
- Лимит попыток ввода (3-5) → инвалидация кода.
- Rate-limit на отправку/повтор SMS: по телефону, по IP, глобальный потолок/сутки
  (защита от накрутки SMS-расходов).
- Лимит заявок с одного IP/телефона за период.
- Проверка ИНН — кэшировать ответ, не дёргать ЕГРЮЛ на каждый повтор.
