# Скилл: публикация каталога в прод

## Архитектура «две БД»

```
┌──────────────────────────┐         ┌──────────────────────────────┐
│  ЛОКАЛЬНО (Mac)          │         │  ПРОД                        │
│                          │         │                              │
│  Парсер / enrichment     │         │  Vercel (Next.js)            │
│        ↓                 │ db:     │        ↓                     │
│  PostgreSQL в Docker     │ publish │  Supabase PostgreSQL         │
│  (источник правды        │ ──────► │  (каталог - копия local,     │
│   по каталогу)           │         │   + заявки клиентов)         │
└──────────────────────────┘         └──────────────────────────────┘
```

Локальный Docker PostgreSQL - источник правды по каталогу.
Supabase - прод, куда летит готовый каталог + живут заявки клиентов.

## Алгоритм публикации

```bash
# 1. Сначала dry-run - смотришь diff local ↔ prod
npm run db:publish -- --dry-run

# 2. Убедился что всё ок - публикуешь
npm run db:publish
```

`db:publish` (`scripts/db-publish.ts`) зеркалирует каталожные таблицы в Supabase одной транзакцией. Читатели не блокируются во время публикации.

## Что публикуется (каталожные таблицы)

- `Category` - иерархия категорий
- `Manufacturer` - производители
- `Product` - товары со всеми полями
- `ProductImage` - ссылки на картинки в R2
- `Specification` - характеристики
- `Datasheet` - даташиты
- `ProductAnalog` - аналоги
- `ImportProgress` - прогресс импорта
- `EnrichmentJournal` - журнал обогащения

## Что НЕ трогается при публикации

- `QuoteRequest` - заявки клиентов, живут только в проде
- `QuoteRequestItem` - позиции заявок, живут только в проде

Эти таблицы создаются только миграциями, данные в них не перезаписываются.

## Картинки

Картинки хранятся в Cloudflare R2. R2-бакет общий для локального и прод окружения - публиковать ничего не нужно. `ProductImage.imageUrl` содержит R2 URL, который одинаково доступен и локально и в проде.

## Переменные окружения для публикации

```bash
DATABASE_URL=...    # локальная БД (Docker)
DIRECT_URL=...      # прямой URL для миграций (тот же Docker)
PUBLISH_DATABASE_URL=... # Supabase прод (для db:publish)
```

## Когда запускать

- После обогащения каталога через enrichment-пайплайн
- После парсинга новых товаров (парсер живёт вне репо)
- После ручных правок в локальной БД (цены, описания, категории)
- Никогда в автоматическом режиме - только явный запуск руками
