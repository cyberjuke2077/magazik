# Скилл: обновление второго мозга

## Шаги

1. Прочитай git log за текущую сессию:
   git log --oneline --since="8 hours ago"

2. Проанализируй что изменилось:
   - Какие файлы затронуты (git diff --stat HEAD~N)
   - Какие решения были приняты
   - Какие проблемы встретились и как решили

3. Обнови docs/business/ если появились новые факты о проекте:
   - Новая архитектурная идея -> docs/business/architecture.md
   - Решение по продукту -> docs/business/product.md
   - Новое про аудиторию -> docs/business/audience.md
   - Изменение целей -> docs/business/goals.md
   - Факт о ценах или экономике -> docs/business/economics.md
   - Канал, воронка или конкурент -> docs/business/marketing.md
   - Всё про запуск в РФ -> docs/business/ru-market-launch.md
   - Добавляй wiki-ссылки [[файл]] на соседние документы

4. Обнови ai-clone/feedback/ если агент делал ошибки:
   - Одна ошибка = один файл по канону:
     name: краткое-имя
     type: feedback
     Правило одним предложением.
     Why: почему появилось.
     How to apply: когда срабатывает.

5. Обнови retrospectives/ файл сессии если он уже есть,
   или создай новый YYYY-MM-DD_тема.md с разделами:
   - Задача
   - Как решали
   - Решили: да/нет/частично
   - Что можно было лучше
   - Что изменить в CLAUDE.md

6. Не дублируй то что очевидно из кода.
   Только то что агент в следующей сессии не узнает без этих файлов.

7. Не добавляй эти файлы через `git add -f` и не коммить.
   Второй мозг намеренно локальный и игнорируется git.
