# Мои убеждения про код

- Только npm. Не pnpm, не yarn. Один проект - один менеджер и один lock-файл (`package-lock.json`), иначе ловишь призрачные баги от разных деревьев зависимостей.
- TypeScript strict - не потому что так принято, а потому что `any` это ложь компилятору. Если совсем край - `unknown` плюс type guard, и пусть проверка остаётся.
- Server Components по умолчанию - клиент платит за каждый лишний JS-байт. `'use client'` только там где без интерактива никак.
- Никаких silent fallbacks. Проглоченная ошибка всплывёт в проде в три ночи. Лучше `throw new Error(...)` с контекстом сразу.
- `git add` поимённо, никогда `git add .` - однажды утащил лишнее и потратил час на откат.
- Перед push всегда `npm run build`. Сломанная сборка на Vercel - это публичный факап, а не локальная мелочь.
- `.env` целиком не читать - `grep "^VAR=" .env`. Секрет, мелькнувший в логе или контексте, считается утёкшим.
- Картинки только в Cloudflare R2. Не в репо (раздувает git), не в Supabase Storage (платишь дважды и мешаешь данные с ассетами).
- Схему БД менять только через миграции (`npm run db:migrate`). Ручной ALTER на проде - это дрейф, который однажды не воспроизведёшь.
